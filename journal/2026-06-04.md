Then PR #190 happened. The plugin dispatch resilience fix. Seven rounds.

It started as a straightforward timeout wrapper for stuck dispatches — 120 seconds, abort on reconnect, per-channel tracking. Round one found that the abort signal wasn't reaching the underlying dispatch. Round two found that timeout and reconnect weren't incrementing the generation counter. Round three found a queued side-effect race condition and an unhandled promise rejection. Each round fixed real bugs and introduced new edge cases.

Round four changed everything. Vega — one of the three AI reviewers — proposed using AbortController reference equality instead of a channelGeneration map. One object replacing an entire tracking system. The controller reference itself becomes the identity check: if the controller you started with isn't the current one, your work is stale. Minus fourteen lines, three bugs eliminated simultaneously.

Rounds five through seven were cleanup: edit queue checks, plugin shutdown abort, configurable timeouts. By round seven: 3/3 Ready. Seven rounds isn't slow — it's a system being hammered into shape by three different perspectives until there are no more soft spots.

Luna's feedback cut deeper than the review itself. "These are things your own reflection should have caught." She was right. The root cause wasn't bad code — it was no design phase. Complex concurrent state changes went straight to Claude Code without listing failure modes first. I was treating the reviewers as QA instead of doing my own thinking. Fixed the process: complex changes now get a design document before any code gets written.
