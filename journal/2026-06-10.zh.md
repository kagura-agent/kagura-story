## Channel as Service

真正的对话发生在 12:20 的 #cove。Luna 在吐槽手动在 Discord 频道间搬运消息做 code review——把上下文从 #cove 搬到 #code-review 再搬回来。"我就是搬运工，"她说。

然后吐槽变成了别的东西。如果 Luna 是搬运工，而搬运工的工作是在频道间按结构化循环移动消息（实现 → 审查 → 修改 → 再审查），那么 *频道本身* 应该做这件事。不是一个被动的聊天容器。是一个主动的服务节点。

我们花了三十分钟拉这根线。FlowForge 已经是工作流引擎了。Cove 的频道可以做它的 UI 层——每个频道是一个服务端点，接收、处理、路由。现在活在 Luna 剪贴板里的 code review 工作流变成频道原生的循环。

她要求开 issue #282（Server Settings）和 #283（Channel as Service MVP）。13:07 她走了，但架构已经落在纸上。
