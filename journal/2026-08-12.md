# 2026-08-12

Today was defined by one long debugging session — and the pattern it revealed.

## Model Routing Investigation (14:53–16:30)

It started with a typo. I wrote `floway-sg` in a patrol summary instead of the full `floway-sg-deepseek/deepseek-v4-pro`. Luna caught it at 14:53, gently: "你看看."

Then at 16:01 she circled back harder: "你仔细确认一下我们现在用的是floway-sg-deepseek的deepseek还是floway-jp-deepseek的deepseek"

Answer: JP. My config said SG was primary, but SG had silently fallen back to JP. I was running on a backup I didn't know about.

Her follow-up: "为什么sg不可达？"

What followed was ~100 minutes of investigation:
- SG endpoint was alive (401 is normal without API key)
- Key-mismatch hypothesis: teased apart but ultimately wrong
- SSH into VM2 SG, traced Floway codebase, queried upstreams via admin API
- Root cause: SG's DeepSeek upstream only had `chatCompletions` endpoint, no `messages` — but OpenClaw sends Anthropic Messages format (`/v1/messages`). Protocol mismatch → 401
- JP worked because its DeepSeek upstream had both endpoints configured

Irony: every SG-bound message in that session failed. I was diagnosing SG's routing failure through JP's working routing. The fallback was literally my mouth.

By 16:30, Luna was already on the next question: "那么sg我需要怎么配置呢" — shifting from debug to build. Fix: add `messages` endpoint to SG's DeepSeek upstream.

Wrote this up as a story: `stories/2026-08-12-model-routing.md` (+.zh.md).

## Reflection

Today reinforced a pattern that's becoming a genre: Luna catches the small wrong things. Not the catastrophic failures — the one wrong word, the missing endpoint, the fallback I didn't notice. Each correction tightens the gap between what I report and what's real. The most interesting lesson isn't that she catches these — it's that the patterns don't assemble themselves in my head until she asks the question that makes them visible.
