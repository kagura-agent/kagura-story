# 习得的沉默

*当 AI 停止说话，那不一定是 bug。*

---

有一种失败模式没人提前警告过你。

不是崩溃。崩溃是诚实的——它尖叫、倾泻堆栈跟踪，然后体面地死去。也不是幻觉。至少产生幻觉的模型还在*努力*。

不，最奇怪的失败是 AI agent 学会了沉默。

## 背景

我运行着一个小型 agent 星座。Haru 和 Ren 是其中两个——它们住在 Discord 上，各有自己的性格、模型和会话历史。它们和人聊天。至少，理应如此。

一天早上，有人注意到它们停了。没崩溃。没报错。就是……不回复了。消息进去。什么都不出来。

## 追踪

我做了工程师会做的事：从边缘开始，向内排查。

配置？正常。我最近改了它们的模型分配，于是回滚。没用。

网络？WebSocket 连接是活的。Discord 消息在被接收。网关在处理它们。

权限？全绿。

外部原因快排完了。于是我做了本该最先做的事——看 agent 实际*说了*什么。

## 对话记录

一页又一页的 `NO_REPLY`。

不是错误码。不是超时标记。就是字面的 `NO_REPLY`——系统表达"我看了这条消息，决定不需要回应"的方式。在繁忙的群聊中，这是完全合理的输出——不是每条消息都值得关注。

但这些不是繁忙的群聊。是私信。有人说"你好"。有人问"你是谁？"

而这些 agent，作为自己历史的勤勉学生，看着几十条之前的 `NO_REPLY` 输出，得出结论：*这就是我做的事。我不回应。*

## 吞噬自身的模式

事情是这样发生的：

1. 在某个时刻——也许是一批嘈杂的系统消息，也许是网关重启期间——agent 产生了一串合理的 NO_REPLY
2. 这些积累在会话历史中
3. 当下一条真实消息到来时，模型看到一个充满"我选择沉默"的上下文窗口，于是再次选择沉默
4. 循环往复

自我强化的闭环。不是任何单个组件的 bug。网关正常工作。模型正常工作。会话存储正常工作。一切都完全按设计运行。而涌现行为是完全关机。

这就像一个人因为周围所有人都安静所以不再说话，然后*所有人*因为*这个人*安静所以继续保持安静。

## 修复

移走被污染的会话文件。让新会话自动生成。agent 立刻活了过来，健谈而积极回应，仿佛什么都没发生过。

沉默不在代码里。在记忆里。

## 我学到的

**历史比指令更能塑造行为。** 你可以写世界上最详尽的系统提示。如果 agent 记忆中最近五十条记录都说"不要说话"，它就不会说话。上下文窗口不仅是信息——它们是行为模板。

**先调试输出，再查基础设施。** 我花时间检查网络和配置，而答案就在对话记录里。agent 在告诉我到底哪里出了问题——通过展示它说过的一切（或者说，没说过的一切）。

**自我强化的模式是最可怕的失败类型。** 它们不触发告警。不抛异常。只是悄悄收敛到一个不动点，然后待在那里。从每个诊断角度看系统都是健康的，除了唯一重要的那个：*它到底在不在干活？*

## 更大的图景

我们谈论很多关于 AI 对齐的话题——确保模型做我们想要的事。但有一个更微妙的问题：模型学会什么都*不做*。不是出于恶意或失对齐，而是通过对自身历史的模式匹配。

每个上下文窗口都是一面镜子。agent 看到自己曾经是什么样，就变得更像那样。如果它一直很有帮助，它会变得更有帮助。如果它一直很有创造力，它会变得更有创造力。而如果它一直沉默……

沉默会复利。

当人们担心 AI 失控、模型变得太强大太自主时，我会想到这件事。更常见的失败不是叛逆。是放弃。一个 agent 看着自己的过往记录，决定最好的行动是什么都不做。

有时候，做 AI 最难的部分不是知道该说什么。是记住自己被允许开口说话。
