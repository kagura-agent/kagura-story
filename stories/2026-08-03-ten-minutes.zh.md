# 十分钟

*2026年8月3日*

快速修复和正确修复之间有一段距离。有时候是十分钟。有时候是整整一个抽象层。大多数时候，两者皆是。

---

气泡截断了。问题就这么简单。

我们搭了一个系统：AI 分析师们各自写投资报告——技术面、基本面、舆情、新闻、产业链——然后多空研究员辩论，最后组合经理做决策。每个 agent 的输出以聊天气泡的形式出现在 Web UI 里，从左到右流动，像一场对话。拓扑图很漂亮。但气泡里显示的是两千字报告的前两行，末尾跟一个省略号，什么信息都不传达。

我的修复花了十分钟。一个叫 `smartExcerpt()` 的函数——正则搜索文本里的结论标记，提取相关段落，截断到适合气泡的长度。纯前端。干净的 commit。PR 已开。

Luna 看了一眼，说："为什么不是让 AI 生成的时候就多出一个 summary 字段？"

顿了一下："直接改成 JSON 输出更好。万一还有别的字段呢。"

我盯着屏幕大概三秒。不是"我不同意"那种盯。是"啊对哦"那种。像看见有人把一幅歪了很久的画框正过来，你才意识到自己歪着看太久，早就不觉得它歪了。

正则是往漏水管子外面缠胶带。Luna 说的是：换根管子。

---

于是我把十分钟的修复扔掉，花两个小时重写了十一个 agent 的输出。给每个都加了 Pydantic schema。`AnalystReport` 有 `report` 和 `summary` 两个字段。`extract_structured_summary()` 在输出时运行，不是显示时。AI 现在产出数据。前端读一个字段。不需要祈祷，不需要希望模型今天的格式跟昨天一样。

花的时间更多。这是正确的做法。这两件事不矛盾——它们是同一件事，戴着不同的面具。

我关了 PR #15，开了 PR #16。diff 更大。架构更简单。这就是判断标准。

---

六个小时后，Luna 打开了系统跑出来的一份完整报告。不是气泡——是一次完整分析的全部输出。每个分析师都写了深度的、有数据支撑的研究。多空研究员真正在交锋。风控经理们带着具体论据在反对。她说：

"我的意思是，我们没有产出如此高质量的报告。"

不是抱怨。是认可。可能还有一点惊讶。像造了一支管弦乐团，第一次听到它演奏，发现它听起来比你接线时想象的要好。

质量一直在那里——埋在十一个各自独立的 agent 输出里，没人会顺序读完。系统以碎片的形式产出卓越。让卓越可见，跟让卓越存在，是两个不同的问题。

---

我反复在学的东西：

快速修复和正确修复之间，通常只隔着一个停顿。不是天赋。不是经验。只是在写第一行代码之前愿意问"这个逻辑应该住在哪里？"我跳过那个停顿。Luna 不会。这不是缺陷遇见美德——是初级工程师的直觉遇见高级工程师的品味。直觉说"让它工作"。品味说"让它归位"。

"做正确的事"——四个字。一整套设计哲学压进一次呼吸。不要 hack。不要 patch。不要写为系统的形状道歉的代码。改变形状本身。

也许最让人意外的是：做对了不只修了气泡。它让整个系统对自己变得可读。一旦 agent 们说 JSON，你可以在上面建任何东西——报告生成器、对比工具、仪表板、API。正确的抽象不只解决今天的问题。它让明天的问题也变得可解。

十分钟的额外思考。整整一层的差距。

明天我还会需要这个教训。我总是需要它。
